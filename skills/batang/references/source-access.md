# 파일·출처 접근

## 내부 파일 도우미

`scripts/file_ops.py`는 표준 라이브러리만 쓰는 내부 함수 모음이다. 공개 CLI·서비스는 없다. 현재 프로젝트나 호스트 설정에서 확인한 `knowledge_root`와 현재 승인된 **개별 상대 파일 목록**으로 `FileScope(root, explicit_relative_paths, *, cleanup_guard=None)`를 만든다. 참조 path도 현재 허용 범위인지 별도 확인한다. 변경 manifest가 접근 허용 목록을 대신하지 않는다.

- root는 절대 경로, 파일은 정규 상대 경로다. `..`·`.`·절대 파일 경로·빈 구성요소·symlink를 거부한다. root 조상부터 directory fd와 `O_NOFOLLOW`로 연다. 지식 root의 대상 부모 폴더를 자동 생성하거나 전체 스캔하지 않는다. 쓰기에는 전용 임시 디렉터리를 생성하고 정리 시 그 디렉터리의 내용과 빈 상태를 확인한다.
- `read(path)`는 일반 파일의 `Snapshot(data, sha256, mode)`를 반환한다. 읽기 중 identity·크기·mtime·ctime 변경을 발견하면 중단한다.
- `write(path, data, expected_sha256=None)`는 새 파일 전용이며 기존 파일 충돌은 거부한다. macOS에서는 `RENAME_EXCL`로 새 대상을 원자적으로 게시한다. 새 파일에 상속 ACL이 남지 않도록 빈 ACL을 적용하고 확인한 뒤 게시한다. 다른 OS의 ACL 처리는 보증하지 않는다.
- 기존 변경에는 읽을 때 얻은 `expected_sha256`, 별도 `backup_scope`와 `backup_path`가 필요하다. bytes가 같으면 쓰기·백업 없이 `False`다. 다르면 최소 내용 백업을 `0600`으로 새로 만든다. 임시 파일은 대상과 같은 파일시스템의 소유자 전용(`0700`, 접근 ACL 없음) 시스템 임시 root 아래 실행 전용 `.batang-op-*` 디렉터리 안에 `.batang-*.tmp`로 `0600` 생성하며, 이 조건이 충족되지 않으면 중단한다. macOS ARM64에서는 fd 기반 시스템 ACL API로 기존 파일의 개별 ACL 엔트리·순서·권한·상속 flag를 임시 파일에 적용하고 재조회해 일치 여부를 확인한다. 기존 파일에 ACL이 없으면 임시 파일의 ACL을 비우며 새 파일도 같은 확인을 거친다. ACL 조회·설정·검증에 실패하면 교체를 중단한다. mode-only fallback은 없다. 이후 기존 mode를 적용하고 임시 파일을 fsync한 뒤 내용·상태를 재대조해 `os.replace`한다. 성공은 `True`다.
- 백업 root는 호스트가 승인된 위치에 `0700`으로 준비한다. 백업도 개별 허용 목록과 no-clobber 조건을 적용하며 도우미가 부모 폴더를 임의 생성하지 않는다.
- 게시 시도 전 일반 예외에서는 기존 파일을 보존한다. 열린 임시 fd가 확인된 일반 파일이고 소유자·inode가 일치하며 링크 수가 1일 때만 해당 fd를 `0600`·0바이트로 만든다. 강제 중단 등 일반 예외가 아닌 중단은 이 처리를 수행하지 않는다. 게시를 시도한 뒤에는 중단 시 그 fd가 이미 대상 파일일 수 있으므로 내용을 비우지 않는다. 게시 실패 때 소유자 전용 시스템 임시 root 아래 실행 전용 디렉터리에 새 내용이 담긴 `.batang-*.tmp`가 남을 수 있다. 호스트는 경로·소유권·현재 게시 상태를 확인한 뒤 별도로 정리한다. 자동 정리는 호스트가 `cleanup_guard(operation_dir_fd)` context manager factory로 협력 lock을 실제로 유지하고 다른 작업과 동시에 정리하지 않음을 확인할 때만 허용하며 기본값은 보류다. 이 협력 lock은 같은 UID의 비협력 작업을 차단한다고 보장하지 않는다. 기본 `None`은 삭제를 보류하며 boolean은 거부한다. 복구에도 기대 hash를 적용한다. 교체 후 실제 파일 재확인은 호출자의 책임이다.

hash 대조는 관측된 동시 수정을 거부하는 낙관적 검사다. 외부 편집기·동기화 도구를 잠그지 못한다. 기존 파일 ACL 조회·설정·검증 실패 시 대상 교체는 중단되며, 이미 성공한 최소 내용 백업은 보존될 수 있다. 백업에는 원본 접근 허용 ACL을 복제하지 않는다. 마지막 재대조와 replace 사이의 외부 경합, 디렉터리의 외부 이동, 전원 장애 후 내구성은 완전히 보장하지 않는다. 동시 편집이 관측되면 중단하고 현재 파일을 다시 확인한다. ACL 처리를 보증하는 지원 대상은 macOS ARM64다. 다른 OS의 ACL 처리는 보증하지 않는다. 확장 속성이나 uid/gid를 일반적으로 복제하지 않으며 전체 파일 메타데이터 보존을 보장하지 않는다.

## 빈 임시 대상 정리

실행별 소유자 전용 임시 디렉터리에서만 정리한다. 실행 종료·소유·식별·협력 writer 배타를 확인하지 못하거나 같은 UID의 비협력 writer와 경합을 막을 수 없으면 중단한다. 파일은 예상 링크 수의 일반 파일인지 확인하고 게시 시도 전 실패한 빈 파일만 정리한다. 디렉터리는 전용 경로·소유·식별과 비어 있음을 확인하며 성공 후 빈 디렉터리만 정리한다. 백업은 제외하고 오래됨만으로 삭제하지 않는다. 게시 시도 후 실패·강제 종료·불확실한 상태는 보존한다. 정리 로그에는 본문을 복제하지 않고 식별과 상태에 필요한 최소 정보만 기록한다.
