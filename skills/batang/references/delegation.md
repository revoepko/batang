# 바탕 업무배정

바탕을 명시 호출한 작업과 그 후속 작업에 적용한다. 무관한 새 작업으로 자동 연장하지 않는다. 업무를 분해하고 직접 처리 또는 위임하기 전에 이 기준을 확인한다. 유효한 원문이 이미 전달됐다면 다시 읽지 않는다.

## 적용과 경계

호스트에 위임 규약이 있으면 승인된 호스트 진입 조항이 허용한 기본 업무 분해·역할 선택·선택적 검토 배정에 이 기준을 적용한다. 별도 규약이 없는 환경에서도 바탕 작업의 배정 기준으로 사용한다. 사용자 지시, 상위 시스템·개발자 지침과 native 역할 지침, 권한, 필수 역할·모델·독립 검토, 프로젝트 예외와 실제 도구·동시 실행 제한은 유지한다. 스킬은 이를 덮어쓰거나 추가 권한을 부여하지 않는다.

기존 호스트 규약이 해당 배정의 대체를 허용하지 않거나 상위 조건과 충돌하면 그 조건을 따르고 바탕 배정 기준이 적용되지 않은 단계와 이유를 보고한다. 필요한 역할·도구나 필수 모델이 없거나 적용할 필수 규약이 불명이면 영향받는 단계를 알리고 필요한 조치를 확인한다. 필수 역할을 자동 대체하거나 부모 자기 검토로 독립 검토를 대신하지 않는다. 실제 역할 이름이 다르면 책임과 역할 지침에 맞는 허용된 역할에 대응한다.

## 책임과 배정

단순 답변·번역·이미 제공된 사실의 정리는 부모가 직접 처리할 수 있다. 역할을 전부 호출하지 않으며, 아래 조건과 실제 권한·역할에 맞춰 선택한다.

| 조건 | 역할과 책임 |
| --- | --- |
| 독립된 파일·심볼·경로 조사 | `explorer`: 근거와 미확인 범위 반환 |
| 여러 구현 영역·계약 변경·불명확한 범위·반복 finding | `planner_normal` 또는 호환 `planner`: 범위·담당·검증 판단과 승인된 위임 결과의 통합 |
| 계약 충돌·큰 구조 변경·근본 재설계 | `planner_expert` |
| 확정된 내용을 여러 문서·절에 반영하며 상호 참조를 함께 맞춤 | `docs_writer`: 확정 사항을 반영하며 새 정책이나 설계를 독자 결정하지 않음 |
| 웹·UI 구현 | `coder_frontend` |
| 범위가 명확한 작은 백엔드·스크립트·설정 | `coder_light` |
| 복잡한 백엔드·인프라 구현 | `coder_heavy` |
| 고정된 최종 변경의 독립 검토 | `reviewer`: 작성자와 분리 |
| 데이터·상태 전이·운영 계약 검토 | `quality_checker` |
| 접근 경계·공격 경로 검토 | `security_checker`; 실제 Daybreak 접근과 모드가 확인되면 허용된 `security_checker_daybreak` |
| 지정된 보안 finding의 동적 검증 | `security_tester` |
| 승인된 앱 조작과 화면 검증 | `app_operator`: 실제 도구와 권한이 있는 경우 |

부모는 배정에 필요한 목표·승인 범위·소유 대상·완료 조건과 필수 정책을 확인하고 필요한 원문 조항과 출처·프로젝트 예외·자료만 전달한다. 자식이 조사할 원자료를 전체 선행 전독하거나 내용을 다시 작성해 인계하지 않는다. 전체 대화, 전체 COMMON 문서 또는 모든 역할 원문을 기본으로 복제하지 않는다. 호스트가 문맥 전달 방식을 선택할 수 있으면 필요한 범위만 전달하는 방식을 선택한다. 이미 문맥에 전달된 유효한 SKILL·호스트 조항은 재사용하고 필수 조항의 누락·변경·불명·오류가 있으면 해당 원문을 확인한다. 경로나 요약만 전달된 것은 원문 수신과 같지 않다. 일반 자식에게 부모의 전체 배정 규약을 재독시키지 않는다. 배정 planner는 필요한 부모 조항도 확인하고, 독립 reviewer는 독립 판단에 필요한 대상과 원문을 직접 확인한다. 자식은 소유 범위의 조사·편집·저장 확인·지정 검증을 자율 완료하고 근거를 반환한다. 오류·권한 부족·범위 확대·위임 밖 필수 결정이 필요할 때 알리며 정상 단계마다 부모 확인을 기다리지 않는다. 부모는 실제 역할·행동·결과를 확인하고 관찰할 수 없는 내부 수신은 미확인으로 둔다.

호스트가 planner의 재위임을 허용하면 배정된 planner는 승인 범위에서 작업자와 필요한 독립 reviewer·checker를 직접 호출하고, 실제 완료를 기다린다. 원래 범위의 누락·충돌은 원 작업자에게 보완을 배정하고 필요한 재검증과 독립 재검토를 관리한다. planner는 원요구별 충족·실패·미확인, 예외와 근거 위치를 대조해 부모에게 취합한다. planner는 직접 제품 파일을 편집하거나 다른 planner를 생성하지 않는다. 호스트가 해당 재위임을 허용하지 않으면 실제 허용된 배정 방식과 필수 조건을 따른다.

최상위 부모는 사용자 요청과 승인 범위, 추가 권한과 최종 종료를 판단한다. 일상적인 작업자 원문 중계나 유효한 근거의 전체 재독은 반복하지 않되, 근거 충돌·권한 예외를 판단하는 데 필요한 확인은 할 수 있다. 독립 검토자의 원문 확인은 유지한다. 호스트가 자식 최종 응답을 자동 전달한다면 이 계약이 그 전달 자체를 차단한다고 보장하지 않는다.

## 역할과 모델 대응 예시

다음은 역할·모델 선택에 필요할 때만 확인하는 기존 Codex 역할 자료의 추천 예시이며 제품 필수 모델이 아니다. 실제 가용성과 적용되는 필수 모델·역할을 확인한다.

| 역할 | Codex 예시 |
| --- | --- |
| `planner_normal` / `planner` | gpt-6-astra / medium |
| `planner_expert` | gpt-6-astra / xhigh |
| `explorer` | gpt-6-luna / medium |
| `coder_light` | gpt-6-luna / high |
| `coder_frontend`, `coder_heavy` | gpt-6.1-sol / high |
| `docs_writer`, `app_operator` | gpt-6.1-terra / medium |
| `reviewer`, `quality_checker`, `security_checker`, `security_tester` | gpt-6.1-sol / high |
| `security_checker_daybreak` | gpt-6-sol / high, 실제 접근·모드 확인 시 |
