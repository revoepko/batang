# 보기: 설명과 요청된 시각화

작성과 검수에는 [공통 표현 지침](../../madi/references/clear-language.md)을 적용한다.

## 설명 방식 선택

호스트는 허용된 원문과 출처를 바탕으로 요청에 답한다. 단순 설명은 글로 제공할 수 있다. 시각화 요청이 있을 때만 준비된 Archify를 사용하며, 접근 범위나 산출 위치는 요청과 프로젝트 권한을 따른다.

간단한 설명은 글, 구조·관계·절차는 요청된 Archify 도식, 선택과 단계 탐색이 도움이 되는 경우 HTML을 선택한다. 개요에서 선택 내용과 상세로 이어지는 깊이는 주제에 맞게 조절하고 필수 조건과 예외를 숨기지 않는다. 모든 요청에 페이지나 모션을 강제하지 않는다.

## Archify 도식

시각화 요청에서 Archify를 선택한 경우 다음 절차를 따른다. 준비된 실행 경로 또는 Node.js가 없으면 필요한 상태를 보고하고 자동 설치·다른 경로 탐색·provider 대체를 하지 않는다.

호스트는 설치된 Archify의 해당 절차와 입력 schema를 확인하고 요청에 맞는 후보를 준비한다. 예를 들어 native diagram의 기존 실행은 작업 디렉터리에서 `node <archify_executable> finalize <type> <candidate.json> <output.html> --quality showcase --json`이다. 실제 경로와 후보·출력·품질 값은 호스트가 확인한 환경과 요청에 맞게 지정한다. 저장소 근거가 필요한 후보는 해당 Archify 절차의 `--repo-root`를 사용한다. 이 명령은 별도 바탕 CLI가 아니다.

호스트는 실제 종료 상태와 반환된 검증 결과 및 산출물을 확인하고 성공·실패·미실행을 구분한다. 정적 경로나 준비 확인만으로 시각화 생성·검증 성공을 주장하지 않는다. 도면 작업의 독립 검토는 [마디](../../madi/workflow.md)를 따른다.

## HTML 예제

[설명 패널 예제](assets/explanation-panel.html)를 복사해 주제와 근거에 맞게 내용을 바꾸어 사용할 수 있다. 예제는 개인 자료를 자동으로 포함하지 않는다. 클릭·선택 탐색을 내용에 맞게 사용하고 필수 조건·예외·비교를 숨기지 않는다. 선택 항목의 필수 조건과 예외는 해당 항목을 선택했을 때 패널 본문에서 바로 읽을 수 있게 한다. 이를 별도의 펼침 조작 뒤에 숨기지 않는다. 선택 버튼 묶음 바로 다음에는 선택한 내용을 보여 주는 패널을 배치하며, 그 사이에 항목별 조건이나 요약을 반복하지 않는다. 모든 항목에 공통으로 적용되는 조건만 선택 영역 위에 한 번 제시한다. JavaScript를 사용할 수 없는 경우에도 각 항목의 본문과 조건을 읽을 수 있어야 한다.

PC와 모바일에 같은 콘텐츠를 반응형으로 제공한다. 모여 있는 선택 버튼 아래 같은 패널을 교체하고 누적하거나 선택 시 스크롤을 강제하지 않는다. 작은 화면에서는 버튼과 바뀌는 내용이 가까이 보이도록 도입부와 여백을 조절한다. 선택식 HTML은 특정 항목으로 바로 연결할 수 있게 하고 인쇄 시 전체 내용을 제공한다. 페이지 내 검색이 숨긴 본문을 찾지 못할 수 있으므로 전체 내용을 보는 경로도 제공한다. 예제는 `#view=항목ID`로 특정 항목, `#view=all`로 전체 내용을 연다.

긴 페이지를 일률적으로 금지하지 않는다. 짧은 보충은 드러난 한 문장으로 쓰며 details나 팝업은 분량과 탐색에 필요한 이유가 있을 때 선택한다. 

시간 변화 자체가 설명 대상인 경우에만 재생 모션을 예외적으로 선택한다. 이때 유한한 사용자 실행과 중첩 방지, 정지·다시 보기, 비활성·화면 밖·reduced motion 변경 시 중단과 자동 재개 금지를 지킨다. 정적 내용만으로도 완결되어야 하며 키보드와 터치를 지원한다. 결과물은 [검수 기준](references/output-review.md)에 따라 확인하고 마디의 독립 검토를 따른다.

## 게시

HTML을 먼저 완결하고 검토한다. Sites 게시가 명시적으로 요청되면 사용 가능한 Sites 스킬과 도구의 절차를 따르고 대상과 공개 범위의 승인 안에서 진행한다. 이미 받은 승인을 반복해 요구하지 않는다. 사용자가 폐기·재생성 등 변경을 명시하지 않았다면 기존 사이트 URL과 접근 범위를 보존한다. 폐기·재생성을 포함해 게시할 때는 검토한 HTML과 게시 결과의 일치를 확인한다. 제작 성공과 게시 실패는 구분한다. HTML 제작 요청만으로 추가 자료 접근·외부 전송·게시 권한이 생기지는 않는다.

초안을 인계한 상태와 완료를 구분한다. 마디 절차에 따라 초안을 고정해 독립 검토하고 finding을 수정한 뒤 재검토하며 필수 검증을 충족한 후 완료를 판단한다.
