# 공통 표현 지침

이 기준은 일반 응답과 지식·설계·실행 기록·README·릴리즈 안내·사이트·도면·템플릿을 포함한 모든 결과물의 작성과 검수에 적용한다. 이 지침을 읽는 것만으로 마디 실행 절차, 새 도구 사용 또는 추가 검토를 요구하지 않는다. 사람이 읽는 결과물이라는 사실은 공개 권한을 뜻하지 않는다.

독자의 목적에 필요한 정보를 골라 도입부에 결론과 사실에 근거한 효과를 제시한다. 누가 무엇을 하는지 밝히고, 중요한 조건은 해당 행동이나 효과 가까이에 둔다. 여러 요청은 각각 완료·실패·미실행을 구분한다. 설명 깊이는 독자가 답을 얻는 데 필요한 만큼 선택한다.

독자가 직접 할 행동과 AI가 내부에서 수행하는 작업 방법을 구분해 설명한다. 필요한 개념은 짧게 정의하거나 실제 행동으로 풀어 설명한다. 주체를 추측하지 않고, 기술 상세는 자료에 연결하더라도 핵심 조건은 본문에 남긴다. 사용자에게 보여 주는 한국어 본문은 자연스러운 경어체로 쓰고, 한 단락에는 한 주제를 담는다. 한글과 영문은 의미와 어조가 같도록 쓴다.

README에는 현행 사용법과 사용에 필요한 현재 제약을 담고, 릴리즈 안내에는 버전별 변경과 사용에 미치는 차이·조치·호환 조건을 담는다. README를 읽은 사람이 누가 무엇을 어떻게 할 수 있는지, 릴리즈 안내를 읽은 사람이 무엇이 달라졌고 사용에 어떤 차이와 조치·호환 조건이 있는지 답할 수 있어야 한다. 실행 보고는 실제 완료와 실패, 영향과 다음 선택을 설명한다. 작성자는 독자의 질문에 답하는 본문 위치를 찾고 원자료의 필수 사실·수치·부정·상태와 대조해 부족하거나 추측한 내용을 고친 뒤 제출한다. 이 자가검수표를 모든 사용자 응답에 노출하지 않는다. 지침 연결이나 시험 통과를 가독성의 증거로 대신하지 않는다.

코드·필드·식별자와 상태값은 정확히 유지하고 제품 버전과 메타데이터 형식 버전을 구분한다. 조건·제약·권한·부정·수치·출처와 미검증 상태를 보존한다. 불필요한 내부 경위와 반복 면책·근거 꼬리·장식적 맺음말은 덜어내되, 가상 예제의 표시와 중요한 권한·위험·제한 및 유효한 출처는 남긴다.

## 상태와 근거의 구분

- 검토(review), 검증(verification), 승인, `PLAN_READY`, `TASK_DONE`, `RELEASE_READY`, `PASS`, `FAIL`, `BLOCKED`, `NOT_RUN`을 서로 대체해 쓰지 않는다.
- 파일 존재, 정적 문서 검사, 설치 선택값, 합성 호출은 실제 호스트 동작·권한·배포·릴리즈의 증거가 아니다.
- snapshot은 이번 run에 고정한 파일 묶음이고, manifest는 파일별 해시 목록이며, pin은 다음 선택값이다. Checkout bundle은 root `SHA256SUMS`에 적힌 각 파일을 먼저 대조한 뒤 그 `SHA256SUMS` 파일 자체의 SHA-256으로 식별한다. 로컬 release 후보의 `candidate-manifest.json`과 archive hash는 별도 근거이며 기존 값을 대체하지 않는다. 설치 link·세션 전달 경로·run snapshot은 구분한다. profile hash는 실제 저장한 profile bytes에서 계산해 run 기록에만 둔다.
- Graphify는 파생 관계이고 Markdown 원본을 대체하지 않는다. Archify는 요청된 설명 산출물이며 요청이 없으면 실행하지 않는다.
- 예시는 형식을 보이기 위한 합성 자료다. 실제 사용자 승인·데이터·검증 결과로 가져오지 않는다.
