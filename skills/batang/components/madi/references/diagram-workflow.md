# 도면 작업 지침

`마디`는 상위 개발·문서·도면 책임이고, `보기`는 `수풀` 아래에서 요청받은 설명·시각화를 맡는다. 이 절차는 도면 작업에 적용되며 Archify는 요청 시 호스트가 이미 준비한 경로로만 실행한다. 프로젝트 계약이나 사용자 승인 범위를 대체하지 않고 새 권한·runtime·설치기를 만들지 않는다.

1. 대상 문서·frame·shape·geometry·layer·잠금과 요청 범위를 확인하고, 범위 밖의 구조를 바꾸지 않는다.
2. 도면의 연결·경로·범례가 원문 설명과 같은 의미인지 확인한다. 정적 도면 검수는 제품·인프라·배포 성공의 증거가 아니다.
3. Archify는 사용자 요청이 있을 때, 호스트가 지정한 실제 경로와 권한으로만 사용한다. 준비 상태를 확인할 수 없으면 `BLOCKED`이며 자동 설치·대체 provider는 사용하지 않는다.
4. 저장, 재열기, 요청된 PNG·SVG·PDF 같은 출력은 별도로 관찰한다. 관찰하지 못하면 `NOT_RUN` 또는 미검증으로 남긴다.

여러 연결이 하나의 목적지로 모이면 각 `source → target` 의미를 목록화하고, 합류 적용 또는 분리 유지의 이유를 기록한다. 가상의 서비스·경로·관측 결과를 추가하지 않는다.
