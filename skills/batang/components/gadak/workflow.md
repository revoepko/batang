# 가닥: 준비와 설정

첫 지원 환경은 Codex / macOS ARM64다. 호스트는 대상 프로젝트의 `AGENTS.md`와 기존 정책에서 `knowledge_root`(절대 경로), `active_index`(root 기준 상대 경로), `backup_root`, Graphify 실행 위치와 `graph_output`, Archify 실행 위치를 확인한다. 값이 없거나 충돌하면 필요한 값만 확인한다. 임의 경로 탐색·전체 볼트 스캔·설정 loader는 만들지 않는다.

Obsidian vault 접근과 Graphify·Archify 지정 경로는 준비 필수 전제다. Markdown은 호스트가 직접 다루고 앱을 매 요청마다 열거나 등록하지 않는다. 필수 경로를 사용할 수 없으면 준비는 `BLOCKED`다. 자동 설치·업그레이드·다른 경로 탐색·provider 대체는 하지 않는다. 도구 skill 표기 버전과 실행 runtime 버전을 동일하다고 추정하지 않는다. Graphify는 관계 작업과 승인된 갱신에, Archify는 요청된 시각화에 사용한다.

설치 호스트는 실제 대상 프로젝트와 기존 전역·프로젝트 서브에이전트 규약을 확인하고 실제 대상·충돌·제안 변경안을 보여주며 [선택형 checker 권장 규약](../../../../examples/AGENTS.md)을 한 번 제시한다. 사용자가 적용을 선택한 경우에만 프로젝트 설정을 변경하며, 선택이 없으면 기존 규약을 유지한다. 이 선택이나 checker 가용성은 일반 지식 조회를 막지 않는다. 바탕은 전역 규약·에이전트 설정·Daybreak 권한을 설치하지 않는다.

기존 자료를 가져올지 확인하고 [가져오기 계약](../../references/import.md)을 따른다. 설치 시 실제 vault를 지정받고 기존 폴더·노트·frontmatter·`.obsidian`을 보존한다. 기존 활성 목록의 형식·경로·포함 파일을 확인하며 존재만으로 채택·덮어쓰지 않는다. 목록 부재·충돌은 새 목록 경로와 포함 파일을 명시 승인받은 뒤에만 생성한다. 기존 vault가 없다는 답을 받으면 Batang 볼트 이름·상위 위치·생성 여부를 확인하고 승인 뒤에만 새 폴더와 합의한 최소 빈 목록을 만든다. 거절·위치 미정이면 생성하지 않는다. 앱 등록·열기는 별도 관측이며 완료를 추정하지 않는다. `.obsidian`과 plugin 설정을 자동으로 수정하지 않는다. 설치·복구 및 새 run의 고정본과 검토 조건은 [마디 절차](../madi/workflow.md)를 따른다.
