# 가닥: 준비와 설정

조회에 필요한 허용 범위와 실행 환경을 준비한 뒤 [고정 호출](../../references/calls.md)을 사용한다. 조회마다 구현을 다시 읽지 않는다.

호스트는 실제 적용되는 프로젝트 정책에서 요청된 작업에 필요한 값만 확인한다. 지식 자료 작업에는 선택된 `knowledge_root`와 `active_index`, 필요한 원본·백업 경로와 권한을 확인한다. 관계 작업에는 Graphify·Python과 `graph_output`, 요청된 시각화에는 Archify·Node를 확인한다. 독립 코드·문서 작업은 운영 vault를 선행 조건으로 삼지 않는다. 값이 없거나 충돌하면 필요한 값만 확인한다. 임의 경로 탐색·전체 볼트 스캔·설정 loader는 만들지 않는다.

선택한 Markdown에 필요한 접근을 확인한다. 직접 조회에는 Graphify와 Archify가 필요하지 않다. Graphify는 관계 작업과 승인된 갱신에, Archify는 요청된 시각화에만 준비한다. 해당 작업의 필수 경로를 사용할 수 없으면 그 단계는 `BLOCKED`다. Markdown은 호스트가 직접 다루며 앱을 매 요청마다 열거나 등록하지 않는다. 자동 설치·업그레이드·다른 경로 탐색·provider 대체는 하지 않는다. 도구 skill 표기 버전과 실행 runtime 버전을 동일하다고 추정하지 않는다.

같은 대상·설정·버전·권한·고정본에 대한 유효한 준비 확인 근거는 실행이 달라도 재사용한다. 관련 변경·오류·불명이 생기면 영향받는 부분을 다시 확인한다. 준비 확인은 전체 기능 시험이 아니다. 같은 고정본의 등록 경로와 root `SHA256SUMS` 각 항목 및 파일 자체 hash의 유효한 근거는 실행 간 재사용한다. 새 등록 선택·설치·전송이나 관련 변경·오류·불명 시 다시 확인한다.

설치 호스트는 대상 프로젝트와 기존 사용자·프로젝트·호스트 규약을 확인한다. 설정 변경은 실제 대상과 충돌을 확인하고 승인된 범위에서만 한다. 기존 모델·역할·권한을 존중하며 새 프로필이나 전역 설정을 자동 생성하지 않는다.

기존 자료를 가져올지 확인하고 [가져오기 계약](../../references/import.md)을 따른다.

사용자에게는 작업할 프로젝트가 호스트로 작업하는 폴더이며 볼트와 같은 위치일 필요는 없다고 설명한다. 도구가 없는 경우 설치 요청과 선택한 범위 안에서 준비하고 실제 준비 결과를 확인한다.

설치 시 실제 vault를 지정받고 기존 폴더·노트·frontmatter·`.obsidian`을 보존한다. 기존 활성 목록의 형식·경로·포함 파일을 확인하며 존재만으로 채택·덮어쓰지 않는다. 목록 부재·충돌은 새 목록 경로와 포함 파일을 명시 승인받은 뒤에만 생성한다.

기존 vault가 없다는 답을 받으면 Batang 볼트 이름·상위 위치·생성 여부를 확인하고 승인 뒤에만 새 폴더와 합의한 최소 빈 목록을 만든다. 거절·위치 미정이면 생성하지 않는다.

앱 등록·열기는 별도 관측이며 완료를 추정하지 않는다. `.obsidian`과 plugin 설정을 자동으로 수정하지 않는다. 설치·복구 및 새 run의 고정본과 검토 조건은 [마디 절차](../madi/workflow.md)를 따른다.
